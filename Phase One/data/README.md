# Bio-Sniff Dataset Documentation

## 1. Purpose

This directory documents the datasets and data-preparation workflow used by the Bio-Sniff Quantum Optimization project.

The dataset supports preliminary inspection of simulated gas-sensor response patterns and environmental metadata. It is not, by itself, a validated source of physical field measurements or sensor-placement scores.

## 2. Dataset Provenance

The current Bio-Sniff dataset is identified as:

`v5.0-RealisticOverlap-BME688-Synthetic`

The dataset is simulation-based and must be described as synthetic throughout the repository, technical report, and hackathon presentation.

The records represent prepared sensor-response patterns and associated metadata. They should not be represented as observations collected from a physical BME688 sensor deployed in a paddy field unless independently verified measurements are subsequently added.

## 3. Dataset Summary

The available dataset index contains 7,920 records and 14 metadata columns.

The metadata includes fields describing:

- Source file path.
- Timestamp, year, date, and hour.
- Crop type.
- Class label and class identifier.
- Growth stage.
- Temperature.
- Relative humidity.
- Atmospheric pressure.
- Field identifier.
- Recommended dataset split.

The dataset includes Rice and Jowar records. Rice records are the initial focus for the Bio-Sniff paddy-field use case.

The dataset also contains individual sensor CSV files. The audit workflow inspects their heater-step and cycle-response columns, including possible saturation and class-specific differences.

The summary above describes the available dataset index; individual file availability and contents should be verified during execution.

## 4. Data Organization

The source dataset is organized by crop, class, and time-related information. A metadata `file_path` field identifies the corresponding individual sensor CSV file.

An illustrative path is:

```text
03_Dataset/
└── 2025/
    └── Rice/
        └── Healthy/
            └── 1748736000.csv
```

The path is an example of the source organization, not a guarantee that this exact file is present in every distributed copy.

The original dataset archive may contain additional directories and feature files. Refer to the archive's provenance information and actual directory listing before assuming a particular file is present.

## 5. Sensor-Response Data

Individual sensor files contain heater-step and cycle-response measurements in tabular form.

The audit workflow checks the structure of these files, identifies relevant response columns, and examines their value distributions.

Some records have been observed to contain values at or near an apparent upper limit of 320,000. This requires quantitative investigation to determine the extent and implications of possible saturation.

A high resistance value must not automatically be interpreted as a particular disease, VOC concentration, or measured field condition.

## 6. Existing Feature Files

The source archive may include precomputed feature representations, including:

- `lstm_latent_features.npy`
- `quantum_features.npy`

The reported dimensions are 7,920 × 256 for the LSTM latent features and 7,920 × 8 for the quantum features.

These files are derived representations, not raw physical sensor readings and not candidate-location utility matrices.

Before using them in a downstream model, verify how they were generated, their sample ordering, the associated labels, the training procedure, and whether any information from validation or test data was used during feature extraction.

## 7. Dataset Audit Workflow

The notebook `notebooks/BioSniff_Dataset_Audit.ipynb` is intended to:

1. Load and inspect the metadata.
2. Identify Rice records and examine class distributions.
3. Check missing values, duplicate records, and file availability.
4. Inspect sensor-response columns.
5. Quantify potential saturation.
6. Compare response distributions across available classes.
7. Export a structured audit report.

The audit report should be generated by running the notebook. Results should not be assumed to exist until the corresponding files have been created and checked.

## 8. Relationship to Quantum Optimization

The sensor dataset and the QAOA placement benchmark serve different purposes.

The sensor dataset provides simulated signatures for preliminary data analysis. The placement benchmark currently uses synthetic candidate utility and pairwise scoring values.

The dataset alone does not specify:

- Nine validated physical candidate coordinates.
- Measured source locations.
- A measured wind field or VOC-plume distribution.
- Calibrated detection probabilities at candidate positions.
- Experimentally validated sensor-placement utility.

To generate scientifically defensible placement scores, a documented sensing model must connect candidate locations, possible source locations, environmental conditions, and expected sensor responses.

Until that connection is implemented and validated, the placement benchmark must remain labelled as a synthetic optimization experiment.

## 9. Data Handling and Reproducibility

When preparing or distributing the dataset:

- Preserve the original metadata and provenance files.
- Maintain the original source-file organization where practical.
- Document any filtering, transformation, normalization, or feature extraction.
- Record random seeds and dependency versions when applicable.
- Keep training, validation, and test partitions separate when fitting predictive models.
- Avoid presenting simulated records as physical measurements.
- Ensure that any redistributed dataset complies with its applicable licensing and usage conditions.

The repository should document how to obtain or regenerate the data rather than silently changing the dataset between reported experiments.

## 10. Limitations

The current dataset is synthetic. It has not established the performance of a physical Bio-Sniff deployment.

Any model accuracy, response distribution, saturation statistic, or optimization score calculated from these records describes the available simulated data and the assumptions of the corresponding implementation.

Physical validation requires appropriately calibrated hardware, documented collection procedures, verified labels, and field experiments.

## 11. Intended Use

This dataset is intended for:

- Data-pipeline development.
- Preliminary sensor-response analysis.
- Testing optimization-input generation.
- Reproducibility experiments.
- Investigating how QAOA could be applied to a constrained sensor-placement formulation.

It is not intended to substantiate real-world disease-detection performance or a validated optimal deployment configuration without additional experimental evidence.
